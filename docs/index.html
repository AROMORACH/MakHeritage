1. Executive Summary & Abstract

Makerere University ("The Hill"), established in 1922, holds over a century of architectural, political, and socio-cultural legacy. Despite its historic significance, students, academic researchers, and campus visitors frequently face challenges in exploring and understanding the historical context of its landmarks due to sparse physical plaques, network volatility, and fragmented archives.

MakHeritage bridges this gap by combining a Flutter mobile application with a Node.js/Express RESTful API deployed on cloud infrastructure (Render & Supabase PostgreSQL). The platform delivers real-time interactive vector cartography using open-source OpenStreetMap tiles, geofenced GPS proximity alerts that automatically trigger Text-to-Speech (TTS) voice narration, chronological timeline filtering (1922–present), offline data caching via SharedPreferences, and a domain-restricted One-Time Password (OTP) administrator portal with interactive map location picking.

2. Problem Statement & Functional Objectives

Spatial & Historical Disconnect

Physical plaques on campus sites are sparse, weathered, or lack deep background information for visitors and freshers.

Network Volatility

Frequent cellular data disruptions on campus disrupt traditional web-only navigation platforms.

Content Governance

Historical archives require strict administrative security controls to prevent unauthorized tampering.

Key Objectives

  • R1 (Interactive Mapping): Render vector maps using flutter_map and OpenStreetMap tiles centered on Makerere (0.3349° N, 32.5681° E).
  • R2 (Audio Guidance): Compute Haversine distance and automatically trigger flutter_tts narration upon entering 50m landmark proximity.
  • R3 (Offline Persistence): Cache JSON payloads locally via SharedPreferences for network-resilient access.
  • R4 (Domain Authentication): Validate admin emails for 6-digit OTP single-use login with 5-minute expiry.
  • R5 (Interactive CRUD Management): Enable authenticated administrators to create, edit, relocate on map, and delete landmark records.

3. System Architecture & Product Design

MakHeritage utilizes a multi-tiered, decoupled full-stack architecture designed for reliable data synchronization and high performance.

Iconic Landmark Archive: Makerere Main Building (Ivory Tower)

Layer Technology Component Responsibility
Layer 1: Mobile Client Flutter, Dart, flutter_map, geolocator, flutter_tts Interactive cartography, GPS location tracking, proximity triggers, voice narration, UI state.
Layer 2: Local Persistence SharedPreferences Cache Stores offline JSON landmark snapshots for instant auto-loading when network is unavailable.
Layer 3: Cloud REST API Node.js 22, Express.js (Deployed on Render) Handles HTTP API routes (/api/landmarks, /api/admin/request-otp, /api/admin/verify-otp).
Layer 4: Cloud Database & Storage Supabase PostgreSQL & Supabase Storage Persistent cloud PostgreSQL relational database and cloud storage bucket for uploaded photo assets.

4. Core Application Functionalities

Feature 1

Interactive Map & Geofencing

Plots high-precision pins across Makerere. Automatically calculates Haversine distance to trigger voice narration when entering 50m proximity.

Feature 2

Landmark Directory & Filtering

Full-text live search and categorical tabs (Colleges, Halls, Infrastructure, Spiritual, Gates). View rich narratives and foundation dates.

Feature 3

Interactive Location Picker

Admin mode allows curators to tap directly anywhere on the live map to set or relocate landmark coordinates with 7-decimal place sub-meter precision.

Feature 4

OTP Admin Authentication

Restricted 6-digit OTP delivery to institutional emails via Mailtrap SMTP and Resend API for secure content curation access.

Feature 5

Cloud Image Upload

Admins can select photos from device gallery or camera, preview, and upload directly to Supabase Cloud Storage.

Feature 6

Offline Payload Caching

Automatically saves network JSON snapshots locally, guaranteeing uninterrupted navigation during campus network loss.
